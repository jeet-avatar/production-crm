## Decisions Made

- **Tarball over per-dir scp:** Single network round-trip + binary stream preservation. Per-dir scp risks SSH line-ending translation in some configs. Critical for Prisma checksum validation (RESEARCH §7.3).
- **Single atomic commit:** Backfill is one logical operation, not 17 independent changes. Per RESEARCH Open Question 3 recommendation. No review value gained from splitting.
- **Cleanup as final Task 1 step:** Tarballs removed on both sides BEFORE Task 2 commit, so the work tree never contained tarball debris. Idempotent: `ls /tmp/phase31-migrations.tar.gz` returns "No such file" on both sides post-cleanup.
- **Force-add convention:** `git add -f` matches established project pattern (Phase 04-01 audit SQL, Phase 03.1-01 verification log). `backend/.gitignore` line 49 explicitly blocks `prisma/migrations/**/*.sql`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Prisma 7.8.0 (via `npx prisma validate`) rejects local Prisma 5.4.2 schema syntax**
- **Found during:** Task 2 Step 6 (`npx prisma validate`)
- **Issue:** Local `backend/node_modules/` is not installed, so `npx prisma validate` pulled Prisma CLI 7.8.0 (latest). Prisma 7 introduced a breaking schema change: `url = env("DATABASE_URL")` in the `datasource` block is no longer supported — connection URL must move to `prisma.config.ts`. This caused the validate command to exit 1 with `Error code: P1012`. Critical: this is NOT caused by the migration backfill — verified by stashing Task 1 changes and re-running validate; same error.
- **Fix:** Invoked Prisma 5.4.2 explicitly via `npx -y prisma@5.4.2 validate` (matches `backend/package.json` declared version of `^5.4.2`). Set a dummy `DATABASE_URL` env var to bypass Prisma 5's environment-resolution check (validate does not connect to the DB). Result: `The schema at /Users/jeet/production-crm/backend/schema.prisma is valid 🚀`.
- **Files modified:** None (no source files touched; this was an invocation-level workaround)
- **Verification:** `cd /Users/jeet/production-crm/backend && DATABASE_URL="postgresql://dummy:dummy@localhost:5432/dummy" npx -y prisma@5.4.2 validate` exits 0 with "schema is valid" output
- **Committed in:** N/A (no code change; documented as a pattern for Plan 03.1-03 and future plans that need to run prisma validate without local node_modules)
- **Pre-existing condition confirmed:** Yes — stashed the 17 newly-extracted migration dirs, ran `npx prisma validate` against the pre-backfill state, got the same Prisma-7-schema-syntax error. The backfill itself did not break validate; the broken validate was already broken before Task 1.
