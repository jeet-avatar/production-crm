Generate the single new migration that captures Phase 4's schema additions, using `prisma migrate diff` against `origin/production`'s schema (which is byte-identical to EC2 prod's schema per RESEARCH §1.1) as the `--from` side and the local `schema.prisma` as the `--to` side. Purpose: When Phase 04 Wave 4 deploys (later), `prisma migrate deploy` walks the migrations directory in order. The 17 backfilled migrations are already in `_prisma_migrations` (no-op). This new migration is the ONE that actually executes against prod DB, adding the Phase 4 columns.

Critical correctness: `EmailTemplate.category` column ALREADY EXISTS in prod DB (predates Phase 4). If we hand-write `ALTER TABLE email_templates ADD COLUMN category TEXT`, the migration will FAIL in production with `column "category" already exists`. Using `prisma migrate diff` from origin/production (which has the column in its schema) → local (which has the column + the new `@@index([category])`) produces ONLY the index DDL — no redundant ADD COLUMN. This is the central reason for using migrate-diff over hand-writing.

Output: One new migration directory + verification log proving the schema and TypeScript build are healthy.
</objective>

Use `prisma migrate diff` to compute the EXACT DDL delta between origin/production's schema and the local schema. This auto-avoids the `EmailTemplate.category` ADD COLUMN trap (column already in origin/production schema → diff only emits the new index).

```bash
cd /Users/jeet/production-crm

# Step 1: Confirm branch + clean state
test "$(git rev-parse --abbrev-ref HEAD)" = "sync/03.1-reconcile-with-ec2" || (echo "FAIL wrong branch"; exit 1)
test -z "$(git status --short)" || (echo "FAIL working tree not clean — Plan 03.1-02 commit must be done first"; exit 1)

# Step 2: Extract origin/production schema to a temp file (--from-schema-datasource needs a real path, not a process substitution)
git show origin/production:backend/prisma/schema.prisma > /tmp/origin-production-schema.prisma

# Confirm the temp schema has the expected size (~1381 lines per RESEARCH §1.1)
wc -l /tmp/origin-production-schema.prisma  # expected ~1381

# Step 3: Run prisma migrate diff from backend/ (where node_modules live)
cd backend
npx prisma migrate diff \
  --from-schema-datamodel /tmp/origin-production-schema.prisma \
  --to-schema-datamodel prisma/schema.prisma \
  --script > /tmp/phase04-migration.sql 2>/tmp/phase04-migrate-diff-stderr.log

DIFF_RC=$?
cd ..

# Diagnostics if generation fails
test "$DIFF_RC" = "0" || (cat /tmp/phase04-migrate-diff-stderr.log; echo "FAIL prisma migrate diff exited $DIFF_RC"; exit 1)

# Step 4: Smoke-read the generated SQL
echo "=== GENERATED MIGRATION SQL ==="
cat /tmp/phase04-migration.sql
echo "=== END ==="

# Step 5: Validate the SQL covers the expected 6 columns + 4 indexes, and does NOT have ADD COLUMN category
echo "--- Smoke checks ---"
grep -q 'ADD COLUMN "stream"' /tmp/phase04-migration.sql && echo "OK has stream column"     || echo "FAIL missing stream column"
grep -q 'ADD COLUMN "apolloPersonId"' /tmp/phase04-migration.sql && echo "OK has apolloPersonId" || echo "FAIL missing apolloPersonId"
grep -q 'ADD COLUMN "apolloRawData"' /tmp/phase04-migration.sql && echo "OK has apolloRawData"   || echo "FAIL missing apolloRawData"
grep -q 'ADD COLUMN "apolloOrgId"' /tmp/phase04-migration.sql && echo "OK has apolloOrgId"       || echo "FAIL missing apolloOrgId"
grep -q '"contacts"' /tmp/phase04-migration.sql && echo "OK lowercase contacts table"            || echo "FAIL missing lowercase contacts"
grep -q '"companies"' /tmp/phase04-migration.sql && echo "OK lowercase companies table"          || echo "FAIL missing lowercase companies"
grep -q 'email_templates_category_idx\|email_templates"("category"' /tmp/phase04-migration.sql && echo "OK has email_templates category index" || echo "FAIL missing category index"

# CRITICAL: assert no redundant ADD COLUMN category (the central correctness rule)
if grep -q 'ADD COLUMN "category"' /tmp/phase04-migration.sql; then
  echo "CRITICAL prisma migrate diff emitted ADD COLUMN category — origin/production schema may NOT have the column. Investigate before committing. RESEARCH §2.1 §7.1 cover this case."
  exit 1
else
  echo "OK migration does NOT contain ADD COLUMN category (expected — column pre-exists in prod DB)"
fi

# Address Open Question 1 (RESEARCH §9 OQ1): grep for apolloId pre-existence in local schema
echo "--- OQ1: apolloId collision check ---"
grep -nE '\bapolloId\b' backend/prisma/schema.prisma || echo "OK no `apolloId` (singular) in local schema — only apolloPersonId / apolloOrgId"

# Step 6: Create the migration directory and move the SQL
mkdir -p backend/prisma/migrations/20260530120000_phase04_stream_apollo_columns
mv /tmp/phase04-migration.sql backend/prisma/migrations/20260530120000_phase04_stream_apollo_columns/migration.sql

# Step 7: Verify the file landed
test -f backend/prisma/migrations/20260530120000_phase04_stream_apollo_columns/migration.sql && echo "OK migration file in place" || (echo "FAIL migration file missing"; exit 1)

# Step 8: Cross-reference against audit SQL — both should cover same 6 columns (column names, not exact SQL)
echo "--- Semantic cross-check vs manual/04-add-stream-and-apollo-fields.sql ---"
for col in stream apolloPersonId apolloRawData apolloOrgId; do
  AUDIT=$(grep -c "\"$col\"" backend/prisma/migrations/manual/04-add-stream-and-apollo-fields.sql || echo 0)
  GENERATED=$(grep -c "\"$col\"" backend/prisma/migrations/20260530120000_phase04_stream_apollo_columns/migration.sql || echo 0)
  echo "$col: audit=$AUDIT generated=$GENERATED"
done
```
