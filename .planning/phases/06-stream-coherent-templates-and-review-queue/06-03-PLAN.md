<objective>
Extend `POST /api/apollo/send-personalized-campaign` with one new optional body field — `requireReview: boolean`. When true, the route still personalizes each contact via Claude + web_search and persists the audit row, but it writes `status='pending_review'` and SKIPS the Resend dispatch step entirely. The response envelope is extended with `queuedForReview` + `queueIds` (additive — existing callers like NetSuiteCampaignWizard Step 4 keep working because they don't read those fields).

Purpose: closes REQ-062. This is the backend hook for Thread 2 (human-in-the-loop review gate) and Thread 3 (Apollo Campaign button) in Phase 6. The signature change is strictly additive — old callers don't pass `requireReview`, so `requireReview === undefined → falsy`, and behavior is unchanged.

Output:
- One additive change to `apollo.ts:875` route handler
- New top-level response fields (`queuedForReview`, `queueIds`) when requireReview:true; absent otherwise
- 5-fallback Claude contract preserved
- Phase 4 firewall preserved
</objective>
